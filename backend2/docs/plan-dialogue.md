# Диалог: модель интерактива

Канон продукта «Слова». Дополняет docs/plan-model.md (§3, §4, §11, §12 читать вместе с этим
файлом; при расхождении этот файл новее — 03.09). Обязательное чтение нарядов DAY-2, SIT-2,
TTS-1, SCENE-RUN, RESQ-1, SCHED-2.

## 1. Одна мысль

Единица интерактива — не карточка, а **обмен репликами**: собеседник сказал → ты ответил →
собеседник среагировал. Тренажёр не показывает карточки с подписями «тебя спросят / ты
ответишь» — он проигрывает диалог сцены и в каждом обмене отдаёт тебе ход. Всё остальное —
настройка строгости твоего хода.

Чем это отличается от Duolingo: диалог не из учебника, а из твоей ситуации и твоих же фраз.

## 2. Слова: сцена и день

- **Сцена** — порция материала: один реальный эпизод («Начало собеседования»). У сцены нет
  даты. У сцены есть **зрелость**: познакомился → применяю → говорю сам.
- **День** — календарная сборка сервера на сегодня: новая сцена (если по расписанию) +
  дозревшие ступени прошлых сцен + разогрев.
- На экранах материал называется сценой («Сцена 2 · Рассказ о прошлом опыте»). Слово «день»
  остаётся только у расписания и у сегодняшней посадки. Фраза «ступень B сцены 1 наступает
  на второй день» — правильная и понятная; «ступень B дня 1 наступает на день 2» — запрещена.
- Ступень едет за карточкой/сценой, не за днём. Одна сцена в календаре может занимать
  1–3 дня в зависимости от раскладки (SCHED-2).

## 3. Сцена как диалог

P2 отдаёт сцену не только полками, но и **цепочкой ходов** — порядком, в котором реплики
звучат в жизни (см. §9, правка P2). Пример:

```
он:  Hi, thanks for joining today.
ты:  Sure, happy to.
он:  Could you tell me about your background?
ты:  My background is in backend development.
он:  What are you working on now?
ты:  I'm building a learning app.
ты:  Could you repeat the question, please?      ← починка, любой момент
```

3–5 обменов на сцену. Полки hear/say/ask остаются (лестница и словарь живут на них);
диалог — порядок ходов поверх полок.

## 4. Экран-диалог

- Пузырь собеседника **сверху**: звучит голосом, текста нет; «Показать текст» доступен всегда.
- Твой ход **внизу**: форма зависит от уровня строгости (§5).
- Ответил — твой пузырь встаёт в ленту, собеседник отвечает следующей репликой цепочки.
- Спасатели доступны в любой момент отдельной кнопкой («Помедленнее», «Повторите») — их
  использование не ошибка, а нормальный ход; засчитывается им как практика.
- Один обмен = максимум **два такта** твоего хода:
  1. **Понял?** — «Что тебе сейчас сказали?», варианты на языке поддержки.
  2. **Ответишь?** — варианты / сборка / сам (по уровню).
  Такт 1 показывается, пока реплика собеседника не закрыла свою зрелость «понимаю»
  (два касания); потом исчезает — реплика звучит, ты сразу отвечаешь.

## 5. Уровни строгости твоего хода = ступени

| Уровень | Что видишь | Что делаешь | Ступень |
|---|---|---|---|
| **B · выбор** | 3 варианта ответа на изучаемом — все реальные фразы плана (дистракторы из соседних сцен, не абракадабра) | выбрал → сказал вслух (закрепление, без оценки) | B |
| **B+ · сборка** | блоки-связки сцены | собрал ответ → сказал | B закрыт, C ещё нет |
| **C · сам** | только пузырь собеседника | говоришь → распознавание → зачёт; скорость ≤3 с | C |

Правила перехода: B → B+ когда выбор закрыт без ошибок дважды; B+ → C в прогоне сцены
(SCENE-RUN). C никогда не первый: страшно. Уровень B — то, что продаётся; он должен
ощущаться игрой.

## 6. Из выученного раньше

Варианты ответа и блоки сборки берутся из **всего плана**, не только из сегодняшней сцены:
на сцене 3 ты отвечаешь фразой, выученной на сцене 1, если она уместна. Механика
дистракторов уже читает весь план — разворачивается в нужную сторону: «уместные» кандидаты
для правильного ответа — по умению (skill_ref) и форме; неуместные — как дистракторы.

## 7. Озвучка — несущая, не украшение

Ярус «понимаю», такт 1, прогон и разогрев перед событием стоят на слушании. Требования:
- реплики читаются лучшим доступным голосом (не compact), с докачкой при первом входе в план;
- темп реплик ниже темпа слов (tts_rate реплик — отдельная ручка матрицы);
- если системный голос жуёт слова на уровне «непонятно» — реплики озвучиваются
  серверным TTS с кэшем (реплик мало, они статичны; решение по цифрам TTS-1).
Никакая реплика не подаётся на слух, пока озвучка не готова (без «тишины вместо голоса»).

## 8. Спасатели — сквозные

- Прогресс спасателей — на пользователя и язык, **не на план**. Новый план продолжает их
  лестницу с места. Освоенные (C + скорость) уходят в редкое поддерживающее повторение.
- Набор = универсальное ядро («помедленнее», «повторите», «напишите», «секунду, проверю») +
  1–2 слота по типу сцены (для собеседования — «Could you rephrase the question?», для
  бытовых — «сколько стоит»). Освоил ядро — подкидываются следующие из пула.
- Карточка спасателя полноценная: перевод, транскрипция, пример в контексте, озвучка.

## 9. Правка P2 (plan_day v0.5, текст архитектора, вносить дословно)

В OUTPUT добавить поле верхнего уровня:

```
"dialogue": [
  { "turn": "role", "ref": "hear[0]" },
  { "turn": "you",  "ref": "say[0]" },
  { "turn": "role", "ref": "hear[1]" },
  { "turn": "you",  "ref": "ask[0]" }
]
```

В SHELF SPECIFICS добавить:

"dialogue — the order in which this scene is actually spoken: an alternating chain of
role turns (refs into hear) and your turns (refs into say or ask). Guide: 3–5 exchanges
(6–10 turns). Every ref points to an existing item of this day. Every say and ask item
should appear in the dialogue at least once; hear items may appear once. Do not invent new
lines here — dialogue only orders the shelves."

Гейты (сервер): card.dialogue_ref_invalid (ссылка вне дня) — карточное фатальное;
day.dialogue_not_alternating и day.dialogue_missing — дневные фатальные; day.dialogue_uncovered
(say/ask вне диалога) — warning-счётчик. Старые дни без dialogue: сервер строит цепочку
парами по skill_ref (нынешняя механика SIT-1) — обратная совместимость.

## 10. Порядок сессии (уточнение §11 plan-model.md)

Разогрев (спасатели + вчерашние непослушные) → слова и связки (знакомство) → **знакомство с
репликами сцены** (A: интро, узнавание) → **диалог сцены** (B/B+: обмены по цепочке) →
цифры на слух → прогон (C, SCENE-RUN).

Знакомство (A) всегда раньше диалога (B) — в одной посадке карточка не проходит обе ступени;
диалог по сцене открывается на следующий календарный день после знакомства.

> **Уточнение DAY-FIX-2 (05.09, DECISIONS п. 266).** Для РЕПЛИК (`hear`/`say`/`ask`) второе
> предложение снято: знакомство с репликами и диалог сцены идут В ОДНОЙ посадке, знакомство раньше
> диалога — карточка проходит ступень A и открывает ступень B в тот же день. Иначе идеал владельца
> для дня 1 («познакомился → диалог») недостижим, а в плане на три дня диалог сцены 2 выпал бы на
> финальный день. Слова и связки открывают B по-прежнему назавтра. Одно касание ступени в день:
> реплика показывается не более одного раза на ступень за день.

## 11. Что это меняет в карте

- **DAY-2** = экраны дня-сцены (принятая серия «День v1») + переименование день→сцена +
  **экран-диалог** как основной режим ступени B (замещает situational_say/ask/hear из SIT-1
  тремя подписанными карточками). Нужна дизайн-серия экрана-диалога — DLG-DES.
- **TTS-1** — озвучка (§7), до DAY-2 или параллельно.
- **SCENE-RUN** — уровень C на том же экране-диалоге, без вариантов.
- **RESQ-1** — сквозные спасатели (§8).
- **SCHED-2** — раскладка сцен по дням от даты (§2).
- P2 v0.5 (§9) подключается в DAY-2.
