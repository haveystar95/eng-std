сервера (`PlanTabState`, `plan_providers.dart`): плана нет · плита дня (не начат / брошен) ·
день закрыт (плита про закрытый сегодня день, если следующий завтра) · план пройден · событие
прошло (`status = overdue` + `overdue_native`) · день 1 пишется (`lesson_status = building`,
опрос раз в 3 с) · день не собрался (`failed` → `POST …/lesson/retry`). Плита — `lib/ui/day_plate.dart`
(4н, свёрнутый размер): строки этапов из `GET /plans/{id}/days/{n}` `stages[]`, вторая строка
текущего — «начни отсюда · N новых слов» (слова `program[]` с `source = today`) или «не закончен · N
карточек»; подвал — «Начать» / «Продолжить» / закрытая карточка на светлой бумаге с галкой 30 и
«Вернутся в день N · K карточки» (`program[].state = failed`). Маршрут — узлы 22, строки 64, фото
48 у сцен (будущие .72), повторение/репетиция tertiary, слот справа — строка сервера (галка у
закрытого, «сегодня»/«завтра» латунью), линия ink до узла «сегодня», мишень события двумя строками
(дата и день недели — по локали), заголовок — `until_phrase` как есть. Спасательный набор —
карточка 21-2b с первой фразой, «все 5 →» раскрывает остальные на месте. Завершённые планы — список
из `GET /plans` (`status = finished`), тап открывает план в режиме чтения (21-7 с «Открыть
коллекцию»). Подсказки первого раза — три на табе и одна при первом закрытии, флаги в `sync_meta`
(`PlanStore`), гаснут после первого действия. Лист «Как устроен план» — один раз после первого
«Начать» (флаг на клиенте), через 320 мс после возврата на таб. Меню плана — `showFloatingContextMenu`
(4в): дата / новый план / коллекция (если `collection_id` есть) / удалить (терракота последним).
Листы даты, нового плана, алерт удаления — по кадрам; удаление → `DELETE /plans/{id}` → 21-1.
Офлайн — последний ответ `GET /plans/current` из `sync_meta` (`plan_current`) под строкой «нет
сети»; без кэша — карточка «Не получилось загрузить план» с «Повторить». Тап по плите — заглушка
кабинета (`plan_day_stub_screen.dart`) с версией контракта (`Plan.versions`), удаляется в DAY-UI.

   `absent`, `program: []`, `metrics: null`, а у дня `cards_total: 0` — хотя `lesson_status: ready`.
   Плита на табе поэтому стоит без пяти строк этапов, которые рисует кадр 21-2, до первого
   «Начать». Клиент здесь не врёт (рисует то, что сказал сервер), но кадр показывает другое —
   вопрос 5.1.
2. **`day.cards_done` не растёт, пока день идёт.** После 39 отвеченных карточек — `cards_done: 0`,
   `minutes_spent: 0`; обе цифры появляются только при закрытии дня (75 / 1). Плита берёт остаток
   из `stages[]` и потому права, но поле контракта до закрытия читать нельзя.
3. **Слот «завтра» достаётся двум дням сразу.** После закрытия дня 1: день 2 — `tomorrow`,
   день 3 (повторение) — тоже `tomorrow`. На маршруте это две латунные подписи «завтра» подряд
   (снимок `21-4-closed`).

**Починено в клиенте по снимкам:**

4. `plan_sheets.dart` — заголовок листа даты: `event_native` приходит отдельным словом с заглавной
   («Приём»), и подстановка как есть давала «Когда Приём?». Приведено к нижнему регистру — так же,
   как это уже делала лента входа.
5. `entry_language_step.dart` + `plan_entry_screen.dart` — язык называется в языке интерфейса
   (`languageNameFor`, новая функция рядом с эндонимами), а не эндонимом: таблица канваса
   (`entry.language.name`, кадр 22-2) пишет «Английский», и лента с подзаголовком превью — строки
   ПРО пару, а не на ней. Остальное приложение по-прежнему показывает эндонимы (это его правило для
   поверхностей НА языке) — вопрос 5.2.

## 4. Самопроверка кода — что переписано

- **Снимки состояний стали тестами.** До этого «состояние сервера → экран» нигде не было закреплено:
  проверка жила в ручном прогоне по симулятору, стоила 30–120 с на тап и не оставалась в проекте.
  Теперь 32 состояния таба, входа и листов снимаются из фикстур за три секунды и падают сами, если
  экран поедет. Харнесс — `mobile/test/support/plan_goldens.dart`: настоящие шрифты (Ahem
  flutter_test'а сравнивать не с чем), заглушка сети вместо ссылок Pexels, выключенные анимации,
  кадр 390 × 844 @2×.
- **Снимается настоящий экран, а не собранный в тесте виджет.** Таб — `PlanTabScreen` с подменённым
  `planTabProvider`; вход — `PlanEntryScreen`, который тест ведёт теми же нажатиями, что и человек
  (цель → «Далее» → «Далее» → «Далее» → опрос сборки); листы открываются тем же вызовом, что с
  экрана. Поэтому снимок заодно отвечает «дойдёт ли экран до этого состояния сам».
- **Фикстуры — ответы живого сервера, а не выдумка.** Правки под состояния, которых у снятого плана
  не было, лежат отдельными функциями с именем состояния (`_allClosed`, `_overdue`, `_lesson`,
  `_tenDays`, `_finished`) — видно, чем именно правка отличается от снятого.
- Две находки из снимков (§3, пп. 4–5) починены в `lib/`, а не в тесте; `languageNameFor` добавлена
  рядом с эндонимами, потому что это правило языка, а не строка одного экрана.
- Из старого наряда ничего не переделывалось: код таба и входа, написанный до перерыва, остался как
  был, кроме этих двух правок.

## 5. Вопросы к архитектору — только блокирующие

1. **Кабинет неоткрытого дня (находка 1).** Кадр 21-2 рисует плиту с пятью этапами и «75 карточек»
   ДО первого «Начать», а сервер до `POST …/open` не знает программы дня. Либо кабинет отдаёт
   план-программу сразу по готовому уроку, либо кадр 21-2 описывает состояние ПОСЛЕ первого входа в
   день и плиту до него надо рисовать без этапов. Клиенту нужна одна из двух версий.
2. **Эндоним или имя на языке интерфейса (находка 5).** Приложение везде показывает эндонимы
   («English»), таблица канваса для плана — «Английский». Сейчас план говорит по-русски, остальное
   приложение — эндонимами. Это осознанное расхождение двух поверхностей или правило поменялось для
   всех?
3. Остальные вопросы — те же, что в §2а (минуты дня, «N с подсказкой», агрегат «фраз и слов в
   работе», пробный пересчёт маршрута, факт пропуска дней, оценка для 7–9 сцен): контракт их не
   отдаёт, и без них кадры 21-2/21-3/21-7/21-10/21-13/22-3a/22-4a рисуются не полностью.
