## 1. От цели пользователя до готового дня

```
 экран цели ──► P-Listen (×2, необязательно) ──► POST /plans ──► POST /plans/{id}/outline ──► P1
                                                                                              │
                                                       PlanOutlineValidator (фатал → повтор P1 ×1)
                                                                                              │
                                                                     PlanScheduler: сцены → дни
                                                                                              │
 POST /plans/{id}/start ──► GeneratePlanDayJob(день 1[, 2, 3 — EAGER_INTRO_DAYS]) ──► claim() ──► P2
                                                                                              │
                                         pairs[] ──► P2J на КАЖДУЮ пару ──(нет)──► P2P ≤2 ──► P2J
                                                                                              │
                                                       explodePairs(): hear / say / ask + цепочка
                                                                                              │
                                                       PlanDayValidator::validate() (с нуля)
                                                                                              │
                                     фатал, адресованы, ≤ ½ карточек ──► P2R ×1 ──► validate() снова
                                                                                              │
                                                  фатал остались ──► markFailed() ──► claim() ещё раз
                                                                     (MAX_ATTEMPTS = 2, иначе failed)
                                                                                              │
                                                       materialize(): коллекция + termы + факты дня
                                                                                              │
                                     fire-and-forget: repairThenEnrich (MECH) · картинки · озвучка
```

### 1.3. Где обрыв даёт «план собирается» навсегда

| обрыв | что видит клиент | почему навсегда |
|---|---|---|
| **воркер умер посреди дня** (kill контейнера, OOM, `PlanSpendNotRecorded` — единственное исключение, которое `GeneratePlanDayHandler` пробрасывает наверх) | «Собирается» | `claim()` перевёл день в `generating`; `markFailed()` не вызван; `claim()` отказывает всему, что не `pending`/`failed`. **Таймаута захвата нет** — ни `RequestPlanDay`, ни `RebuildPlanDay` такой день не переберут. Выход только руками в базе |
| **задача не поставлена** (Horizon стоял, очередь потеряна, `EAGER_INTRO_DAYS` не сработал) | «В очереди» | статус `pending`, попыток 0; клиент поллит `generate`, а `RequestPlanDayHandler` — единственное, что ставит джобу заново; если и он молчит — вечное «в очереди» (живой Д-20 в `plan-map.md` §3.1) |
| **суд пар бесконечно платит** — не навсегда, но дорого: 5 пар × (1 + 2 переписки + 2 пересуда) = до 25 вызовов на попытку, × 2 попытки | «Собирается» дольше минуты | капа на СУММУ вызовов суда нет; есть только «≤ 2 переписки на пару» |
| **обе попытки P2 отбиты** | «Не собрался» (`failed`, `fail_code`) | честный тупик, не вечный: «Собрать заново» (`rebuild`) даёт ещё 2 попытки |

## 2. Промпты — что просит, какие правила есть, каких нет (против канона Ч.2)

### 2.1. P-Listen v1.1 (`plan_listen.v1.1.md`, `PlanListenService`)

**Просит:** три реплики собеседника в ситуации (4–12 слов, три разных момента, без чисел и имён) с
переводом и меткой места, плюс два продолжения цели на языке поддержки. Пустой `target_lang` →
только продолжения.

**Правила есть:** spoken register, level-appropriate, три разных момента, счёт — ориентир.

**Правил нет (и не нужны):** до плана дела не имеет, реплики не становятся карточками. Вне канона
Ч.2 по замыслу; в наряде не трогается.

### 2.2. P1 v0.4.1 (`plan_outline.v0.4.1.md`, `PlanOutlineService`)

**Просит:** `goal_summary` + `scenes[]`: `position`, `title` (2–4 слова, без двоеточия), `intro`
(2–3 предложения на языке поддержки), `skills[]` (`outcome`/`checkpoint`/`est_terms`/`topics`),
`opening_lines[]` (3–6 реплик собеседника на изучаемом), `entities[]`.

**Правила есть:** сцена = один реальный эпизод («Medical vocabulary» — не сцена); порядок
типичное→редкое; вводка без изучаемого языка; умение = одна способность без «и»; 3–12 умений на
план; без умений о базовом; дни не планирует.

**Правил нет по канону Ч.2:**
- «сцены не повторяют друг друга по теме» — не сказано; валидатор дублей сцен не смотрит;
- «роль названа» — просится косвенно («who they face» во вводке), гейта нет;
- название сцены «про ситуацию, не про грамматику» — есть только «2–4 слова»;
- **число сцен ≠ число дней до события**: P1 календаря не видит; `PlanScheduler` режет лишние
  сцены с конца и никогда не ДОБИРАЕТ — план на 5 дней с двумя сценами останется на 2 учебных дня.
  (Это по замыслу: «дней столько, сколько сцен».)

### 2.3. P2 v0.6 (`plan_day.v0.6.md`, `PlanDayComposer`)

**Просит:** `pairs[]` (4–5, не меньше 4; `kind: answer|ask`; `role` ≤ 12 слов, `you` 3–8 слов
собранной; хотя бы одна `ask`; в `you` — хотя бы один уточняющий вопрос и одна починка),
`words[]`/`chunks[]` (вместе 4–6, с `example`), `numbers[]` (2–4). У каждой карточки `skill_ref`,
`frame` + `filler`, `translation` собранной фразы; `transliteration` при разных письменностях.

**Правила есть:** «you — прямой ответ на ЭТУ реплику» с примером; `ask` = приглашение, не вопрос;
spoken register, natural word order, one thought per line; связка — самодостаточный кусок языка;
перевод связки точь-в-точь; стоп-список базового; имена — только наполнители; ключ реплики —
слово/связка дня; без клонов; формулы — меньшинство; баланс hear/say по шагу слуха.

**Правил нет по канону Ч.2:**
- **переспрос не ответ**: наоборот — промпт ТРЕБУЕТ «at least one clarifying question and at
  least one repair move» среди `you`, то есть сам кладёт «Sorry, do you mean…?» в полку ответов;
  канон говорит, что в «ты ответишь» — только ответы (починка — спасатели, уточнение — полка `ask`);
- **простота уровня**: «3–8 слов» и «spoken register» есть, но нет «сказал бы так человек уровня
  basic?», нет запрета канцелярита («I was responsible for…»), нет шкалы basic 4–8 / intermediate
  ≤ 12;
- **speaking_keys[]**: один ключ (`filler`), варианта проще нет вовсе — ни в промпте, ни в схеме,
  ни в таблице;
- **перевод ровно по смыслу** («без добавок из контекста сцены и без пропусков») — сказано только
  про связку («Translate the chunk's text exactly»), про реплику — «translation of the WHOLE
  assembled sentence» и «must contain the translation of the key», т.е. про полноту, но не про
  отсутствие добавок;
- **слово стоит в реплике** — есть косвенно («Lines of the day must be combinable with … words and
  chunks»), прямого «слово, которого нет ни в одной реплике, в день не попадает» нет;
- **один связный разговор** — «the conversation as EXCHANGES, in the order they happen» есть, но
  «не список несвязанных вопросов» не сказано; 4–6 пар канона против 4–5 промпта.

### 2.4. P2J v0.1 (`plan_pair_judge.v0.1.md`, `PlanPairCourt::judge()`)

**Просит:** один вопрос — «B — прямой естественный ответ на A?» → `{fits, reason}`.

**Правила есть:** для вопроса — ответ на ЭТОТ вопрос; для приглашения — вопрос по сцене; для
утверждения — реакция (acknowledge, clarify, **ask to repeat**, thank).

**Правил нет по канону Ч.2:** судья ЯВНО освобождён от всего остального — «Register and length do
not matter; only whether B follows A». Значит:
- переспрос («Sorry, do you mean the users?») судья ЗАСЧИТЫВАЕТ как ответ (это «clarify»);
- канцелярит проходит;
- перевод судья не видит вовсе (на вход едут только A и B);
- уровень не спрашивается (`{{level}}` в P2J не передаётся);
- температура вызова — дефолт вендора (адаптер `temperature` не задаёт) → вердикт «да/нет» на
  спорной паре не воспроизводим.

### 2.5. P2P v0.1 (`plan_pair_rewrite.v0.1.md`, `PlanPairCourt::rewrite()`)

**Просит:** новую `you` (3–8 слов, `frame`+`filler`, ключ из DAY WORDS, перевод, чтение,
`skill_ref`) — прямой ответ на A.

**Правила есть:** ответ на этот вопрос / вопрос на приглашение / реакция на утверждение; ключ не
базовое слово, не имя; перевод содержит перевод ключа.

**Правил нет:** нет запрета переспроса (пункт «react» его разрешает); нет простоты уровня, кроме
`{{level}}` в шапке; нет «перевод ровно по смыслу». Переписанная реплика потом проходит валидатор
дня, но НЕ проходит проверку «слово дня стоит в реплике» как обязательство — только счётчик.

### 2.6. P2R v0.2 (`plan_day_repair.v0.2.md`, `PlanDayRepairer`)

**Просит:** вернуть ровно сломанные карточки, починенные, по адресам (`array`,`index`).

**Правила есть:** реплика чинится целиком (`frame`+`filler`); пример — новое предложение; перевод —
ключ «ничего не потеряно, ничего не добавлено» (единственный промпт, где «без добавок» сказано
прямо); реплика — «spoken turn at level {{level}} length, not a textbook sentence».

**Что важно для наряда:** P2R чинит карточку ПО АДРЕСУ ПОЛКИ и не знает о парах. Починив `say[2]`,
он не пересуживает пару (`hear[2]` → новая `say[2]`) у P2J — **починенная реплика может перестать
отвечать на свою реплику роли, и никто этого не увидит** (см. Ч.4.3).

## 3. Что проверяет `PlanDayValidator` (по форме) и чего не проверяет

**Фатальные карточные:** дырка (`card.gap_missing/_outside_frame/translation_has_gap`), ключ в
переводе (`card.translation_missing_key`, только `say/ask`, по основам 5 букв для ru/uk), клоны
(`card.clone` — с другими карточками дня, спасателями, известным), пример = карточка
(`card.example_is_a_term`), пример без своего слова у `words/chunks` (`card.filler_not_card`),
скелет-клон примера, пример без перевода, базовое слово (`card.word_is_basic`, от `basic`
фатально), связка из базовых / артикль+сущ., размеры (`card.kind_size`: word ≤ 3, chunk 2–4,
say/ask 3–8, hear ≤ 12), имя как карточка, перевод = транслит, `skill_ref` не из сцены, число не
звучит в реплике, ссылка цепочки.

**Фатальные дневные:** `day.pairs_too_few` (< 4 пар после суда), `day.shelf_missing`
(`hear`/`say`/`words+chunks` пусты), `day.dialogue_missing/_not_alternating`.

**Счётчики (никогда не отбивают):** размеры полок вне ориентира, доля формул, нет вопроса, нет
починки, умение без карточки, **слово вне реплик (`plan_day_substitution_outside_frame`)**,
пересказ вводки, `filler` не карточка дня у `say/ask`, дубль перевода, нет картинки, ключ не на
языке поддержки, реплика вне цепочки, пример содержит реплику, у `hear` перевод без ключа.

**Чего не проверяет никто (ни валидатор, ни судья):**
1. переспрос/уточнение в полке `say`;
2. канцелярит / простота уровня (только длина в словах);
3. точность перевода (добавки из сцены, пропуски) — есть только «ключ присутствует»;
4. слово/связка, не стоящие ни в одной реплике, — **счётчик, а не отбой**;
5. дубли реплик МЕЖДУ сценами (днями): `card.clone` знает `knownTexts` = термины прошлых дней
   (`KnownTermsReader::metInPlan`) — это покрывает повтор слова, но день 2 и день 3 пишутся
   ВПЕРЁД (`EAGER_INTRO_DAYS = 3`), и день 3 не видит день 2, если тот ещё не записан;
6. вариантов ключа нет — проверять нечего;
7. связность разговора (пары как ОДИН эпизод, а не пять несвязанных вопросов);
8. что `role` пары `ask` — приглашение, а не вопрос (просьба в промпте, гейта нет).

## 4. Ретраи и починка — сводка

| механизм | где | что теряет |
|---|---|---|
| повтор P1 | `PlanOutlineService::attempt()` ×2 | ничего: второй ответ целиком новый |
| суд пары | `PlanPairCourt::hold()`, ≤ 2 переписки | переписка меняет ТОЛЬКО `you`; `role` и `skill_ref` (если модель не сменила) остаются; выброс пары забирает и `role` |
| P2R | `PlanDayRepairer::merge()` | карточку по адресу; **пара не пересуживается**; цепочка не меняется (адреса стабильны), т.е. пара с починенной `say[i]` остаётся парой; `speaking_key` считается заново при записи |
| повтор дня | `FinishPlanDayHandler` → `claim()` | всё: новый ответ P2, суд заново; в сообщение едут только адреса и коды прошлой попытки |
| станок/картинки/озвучка | после `ready` | ничего в дне; при падении — нет форм/дистракторов/картинок |

## 5. Что из этого — база «было» для Ч.3–Ч.6

- Полка «ты ответишь» = `say`; переспросы туда кладёт сам промпт (§2.3).
- Простота реплик держится на трёх словах «spoken register» и потолке 8 слов.
- Перевод судится только на наличие перевода ключа.
- Один ключ (`terms.speaking_key`, `PlanSpeakingKey::of()` при записи; грейдер
  `SubmitReviewsHandler::expectedFor()` → `ExpectedAnswer([$speakingKey], Coverage)`; сам грейдер
  уже умеет список `accepted[]` — `AnswerGrader::grade()` перебирает кандидатов).
- Слово вне реплики — счётчик.
- Судья пар: один вопрос, температура по умолчанию, ответа «в чём именно» нет.
