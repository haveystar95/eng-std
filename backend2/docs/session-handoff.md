## ВТОРОЕ: разбор ошибок больше не цитирует ответ — это и было причиной

DECISIONS п. 201. Накопительный список нарушений (п. 199, вторая половина) цитировал ТЕКСТЫ карточек
первой попытки, и третий живой вызов вернул ровно эти реплики вместе с дефектами, которые вторая уже
починила. Подробный разбор чужого ответа, внутри которого стоит сам ответ, работает как ОБРАЗЕЦ.

Теперь у нарушения есть **адрес**: `array` + `index` + `field` + код + английская причина про эту
карточку и только про неё (`PlanViolation::address()`). Русский `detail` с процитированной карточкой
остаётся человеку в `fail_reason` и в логе и к модели не едет никогда. Повтор целого дня получает
адреса ПОСЛЕДНЕЙ попытки, без накопления; тест на фейк-адаптере проверяет, что в блоке нарушений нет
ни одной строки предыдущего ответа длиннее 12 символов.

**Нарушение без адреса** (счёт карточек, незакрытый чек-пойнт, дублированный чек-пойнт) — это
нарушение об ОТВЕТЕ: чинить по карточкам нечего, такой день идёт назад целиком.

## ТРЕТЬЕ: как теперь считаются деньги дня

`learning_plan_days.generation_attempts` считает **платные вызовы**, а не запуски задачи. Потолок —
2. Запуск тратит один вызов (P2) или два (P2 + P2R), и во втором случае бюджет исчерпан сразу: день
`failed`, третьего ответа не покупается. У дня ровно две развилки, и обе стоят одинаково:

- сломано **больше половины** карточек (или есть нарушение без адреса) → P2R не зовётся, день
  перезаказывается целиком, во втором сообщении только адреса;
- сломано **не больше половины** → один вызов P2R, слияние по (`array`, `index`), день судится
  целиком заново обоими гейтами.

До v0.3 потолок был 2 × 2 = 4 вызова. P2R пишет свою строку в `generation_requests`
(`purpose='plan'`, `day_repair: починка дня N — карточек K`).

## ЧЕТВЁРТОЕ: что стало счётчиком, а что осталось фатальным

Понижены до warning-ов ДВА гейта (решение архитектора, п. 201):

- `plan_day_substitution_outside_frame` — слово, не встающее в дырку ни одного каркаса. Последний
  фатальный гейт между живым днём и `ready`: три захода подряд, всегда ОДНА карточка из
  четырнадцати;
- `plan_day_role_line_share` — потолок реплик собеседника, на то же основание, что и его пол
  (`plan_day_no_role_line`).

**Фатальными остались** (полный список, по одной строке «почему»):

| код | почему фатален |
|---|---|
| `day.array_count`, `day.term_count` | день не того размера, который просил юзер минутами |
| `day.checkpoint_uncovered` | этот день физически нельзя пройти |
| `day.checkpoint_on_word` / `..._out_of_range` | чек-пойнт закрывается репликой и существующий |
| `day.kind_mismatch` | карточка врёт о том, что она такое; ступени выдаются по `kind` |
| `day.frame_slot_count` | две дырки на один наполнитель — реплику не собрать |
| `day.filler_mismatch` | дырка без наполнителя / наполнитель без дырки — собирать нечего |
| `day.filler_not_a_card` (только `en`) | в дырке слово, которого день не учит |
| `day.slot_outside_frame` | поле с `___` юзеру не произнести |
| `day.role_line_invented` | юзер готовится к реплике, которой в сцене нет |
| `day.example_is_a_term`, `day.example_duplicated`, `day.example_missing` | карточка без своего примера ничему не учит |
| `day.key_is_the_term`, `day.key_duplicated`, `day.key_not_support_language` | ключ, по которому нельзя восстановить ответ |
