# Страница плана ученика в админке (наряд ADM-1)

Одна страница `wt_admin`, на которой видно всё о плане ученика: почему день упал, сколько он стоил, чьим голосом
озвучена реплика, что говорила роль в разговоре, что ответил ученик. **Только чтение**: ни кнопок действий, ни покупок,
ни изменений плана — это ADM-2 / ADM-3. Решение — `docs/DECISIONS.md` п. 402.

## Вход

- **Ученики → карточка ученика → вкладка «Планы»** (`/users/:id/plans`): код, название, статус, дата события,
  «день N из M», итого $. Клик по строке — страница плана.
- **⌘K**: код плана (6 символов, регистр не важен — `nkkgff` = `NKKGFF`) или полный id → страница плана.
- Прямой адрес: `/plans/NKKGFF`, день — `?day=2` (ссылка открывает ровно то, что видел отправитель).

**Код плана** — символы 5–10 его ULID: `01M2NKKGFF8H7TQG8HB75NRJP1` → `NKKGFF`. Если код общий у двух планов, сервер
отвечает 409 с их id — такой план открывается по полному id.

## Страница

Одна длинная страница в бумажном стиле; слева липкое оглавление, сверху фильтр **«весь план / день N»** — он сужает
ВСЕ разделы сразу. У каждого блока — **«JSON»** (сырой ответ эндпоинта, как пришёл) и **«скачать .json»**. Статусы —
одним набором чипов (`StatusChip` + `utils/planLabels.ts`). Деньги всегда с единицами: модели — токены туда/обратно · $,
голос — кредиты · символы · $. Чего в базе нет — «н/д» и строка «не хранится: …» в блоке.

| Раздел | Что показывает |
|---|---|
| Шапка | код, название, ученик (ссылка), языки, уровень, событие, статус (действующий и в базе), создан, прогресс «день N из M · открыт K · пройдено», версии промтов (план / урок / судья слотов / агент разговора; P2R и судья швов — н/д), хеш сборки сервера, итого $ |
| Что не так | находки 11 проверок (ниже), ошибки первыми, у каждой — день и место (строка, карточка, ход, вызов); пусто — «План здоров» |
| Обзор | дни: №, вид, сцена, дата по расписанию, статус дня (как его видит клиент: `building`, пока урок следующего дня не готов), статус сборки, прохождение (когда, минуты, карточки, есть ли запись итога), цена дня; «JSON» на строке |
| Конвейер генерации | job плана → урок (каждая попытка из журнала) → валидатор (коды, фатально/предупреждение по `LessonGate::FATAL`) → P2R → судья швов → картинки → озвучка → выдан клиенту; у этапа статус, время, длительность, модель, промт, токены · $, вызовы со ссылкой на `model_calls` и «запрос и ответ» свёрнуто |
| Урок и голос | урок в выданном виде (обмены с каркасом и наполнением, `in_dialogue`, фразы, слова, слушание, проверки, возвраты); таблица озвучки: строка, роль, голос (роль · пол · короткий id по конфигу пакета), правило выбора, модель, кредиты · символы · $, дата, «послушать», статус (озвучена / телефонный голос / нет); фильтры «без звука», «телефонный голос» |
| Прохождение | карточка за карточкой в порядке ответа: вид, что ожидалось, что ответил ученик (для речи — что услышало распознавание), вердикт (код / судья-модель), попытки, время; итог дня; клиент — User-Agent и последняя синхронизация, версия сборки и устройство — н/д |
| Разговоры | каждый разговор: конструкции сцены (сказана / частично / нет, каким ходом засчитана, каким ходом роль открыла), стенограмма по ходам (текст, звук, распознанное, «открывает конструкцию», вердикт, задержка, $ хода), причина завершения; «скачать стенограмму .json» |
| Деньги | по этапам × дням: генерация (урок · P2R · судья — если журнал говорит точно), фото (н/д), голос, разговор (модель и голос), судья слотов; итог по плану; сравнение с каноном |
| Вызовы API | единый журнал: вызовы модели, покупки голоса, судьи слотов, обращения клиента; фильтр по источнику и дню; lost и ошибки подсвечены; постранично («Загрузить ещё» по курсору) |

## Эндпоинты (`/admin/api`, только GET)

| Эндпоинт | Назначение |
|---|---|
| `GET /users/{id}/plans` | планы ученика для вкладки «Планы» |
| `GET /plans/{code}` | шапка |
| `GET /plans/{code}/issues?day=` | «Что не так» |
| `GET /plans/{code}/days?day=` | обзор дней |
| `GET /plans/{code}/pipeline?day=` | конвейер генерации |
| `GET /plans/{code}/lesson?day=` | урок и голос |
| `GET /plans/{code}/passage?day=` | прохождение |
| `GET /plans/{code}/conversations?day=` | разговоры |
| `GET /plans/{code}/money?day=` | деньги |
| `GET /plans/{code}/calls?day=&source=&limit=&cursor=` | журнал вызовов, курсор `meta.next_cursor` |
| `GET /plans/{code}/audio/{audioId}` | звук строки сцены или хода разговора этого плана (чужой id — 404) |

Контракт — `backend2/openapi/openapi-admin.yaml`, тег «Plan page». Сборку делает модуль Plan
(`Plan/Application/Inspection/PlanInspection`), Admin только зовёт (`GetPlanPage`, `GetPlanCalls`, `GetPlanAudio`,
`ListLearnerPlans`). Журнал вызовов и лог запросов Plan читает через свой порт `PlanCallJournal` поверх
Observability `CallLogReader`.

**Как вызов модели попадает на страницу.** `model_calls` не называет плана. Вызов считается вызовом плана, когда начат
в окне его сборки под назначениями окна: сборка плана (`plan`, до строки `plan_ready`), урок сцены (`lesson`, `repair`,
`judge`, до строки `day_ready` этой сцены — `generated_at` для этого не годится, оно пишется моментом начала сборки),
разговор (`conversation`, до конца). Сборка без известного конца (готовая сцена без `day_ready` — до PLAN-UI-3) окна не
получает: у неё `updated_at` уходит на дни вперёд, и туда попали бы судьи слотов прохождения (они тоже `judge`).
Проверка на данных: разбивка урок + P2R + судья по журналу сходится с хранимой ценой сцены до цента (зал, день 1:
$0.107065 + $0.001721 = $0.108786; ветеринар, день 1: $0.084736 + $0.007307 + $0.001670 = $0.093713). У окна `others` — сколько окон ЧУЖИХ планов его
пересекают; при `others > 0` вызов помечен «окно общее» (`certain: false`) и разбивка цены урока не даётся. Окно есть
только у последней сборки сцены: `build_started_at` перезаписывается пересборкой. «Запрос и ответ» — строка лога
исходящих, совпавшая с вызовом по usage (токены туда и обратно) внутри окна вызова; нет точного совпадения — н/д.

## Проверки «Что не так»

Каждая — отдельный чистый класс `backend2/app/Modules/Plan/Domain/Inspection/Check/*`, тесты на канон —
`backend2/tests/Unit/Plan/Inspection/PlanChecksTest.php`. Проверки только показывают; чинит — FIX-4.

| Код | Что ловит | Вес |
|---|---|---|
| `sound_text_mismatch` | звук строки на карточке — файл другой строки урока (текст урока по `audio.ref` ≠ текст карточки; `___` на карточке — окно, в нём что угодно); файл куплен для другого текста, чем у строки сейчас (текст из лога вендора, если вызов найден однозначно) | ошибка |
| `voice_gender_mismatch` | строка куплена только голосом другого пола своего говорящего (ученик — пол профиля, собеседник — пол роли, п. 389); ход роли в разговоре сказан не голосом сцены | ошибка |
| `line_without_sound` | у строки нет файла голосом по правилу — звучит телефон (или у языка нет голоса) | внимание |
| `day_failed` | урок дня `failed`, с причиной (`fatal: <коды>`) | ошибка |
| `scheduled_day_not_ready` | день открыт по расписанию (дата пришла, прошлый закрыт), а урок не `ready` | ошибка |
| `building_out_of_line` | урок пишется (`building`/`illustrating`) не для следующего в очереди дня | внимание |
| `lost_model_call` | вызов модели плана в состоянии `lost` | ошибка |
| `day_cost_over_canon` | генерация + голос дня > $0.16; починки P2R > 10 % цены генерации (только когда журнал говорит точно) | внимание |
| `passed_without_summary` | день закрыт, а строки `day_passed` в журнале плана нет | внимание |
| `talk_without_openers` | роль говорила, но ни одна её реплика не открыла конструкцию (`opens_target` пуст на всех ходах) | внимание |
| `talk_ended_by_limit` | разговор закончился по лимиту ходов, минут или денег, а не прощанием | внимание |

Канон денег — `backend2/config/plan.php` → `plan.inspection` (`PLAN_CANON_*`).

## Не хранится (что страница показывает как «н/д»)

- связь `model_calls` с планом, сценой, днём, разговором (только окна времени);
- версия промта P2R и судьи швов у плана/сцены;
- какую карточку чинил P2R и «было/стало» (`lesson_json` перезаписан), находки валидатора до починок;
- окна вызовов ранних сборок сцены (`build_started_at` перезаписывается);
- время конца сборки урока: `plan_scenes.generated_at` пишется моментом её начала (конец — только строка `day_ready`);
- причина телефонного голоса (402 вендора, предохранитель, кап) — только лог приложения и `failed_jobs`;
- время и цена поиска фото;
- версия сборки клиента и устройство (клиент их не присылает — только User-Agent `Dart/…`);
- сырой текст распознавания и альтернативы (сервер получает только строку `heard`), время показа карточки;
- время вызова судьи слота (есть только `answered_at` карточки);
- обращения клиента за звуком и фото — их адреса не несут id плана.
